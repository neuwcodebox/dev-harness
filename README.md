# Dev Harness

AI와 충분히 논의한 프로젝트 계획을 **요구사항·설계·개발 계획이 연결된 워크스페이스**로 정리하는 템플릿이다. 새로운 요구사항을 수집하는 설문이나 에이전트 실행 프레임워크가 아니라, 가벼운 소프트웨어 개발 체계와 다음 세션에 이어줄 프로젝트 맥락을 제공한다.

## 사용하기

템플릿을 새 프로젝트에 복사하고, 계획을 논의한 대화에서 아래 프롬프트를 전달한다. 새 대화에서는 합의한 계획을 함께 제공한다. 기존 프로젝트라면 덮어쓰지 않고 현재 코드·문서에 통합한다.

```text
지금까지 합의한 프로젝트 계획을 바탕으로 이 템플릿을 채워 개발 워크스페이스를 완성해 줘.
AGENTS.md와 문서별 양식을 따르고, 목표·설계·계획·검증의 연결과 누락을 확인해.
초기화만 진행하고 구현은 시작하지 마.
```

초기화가 끝나면 합의한 범위가 문서에 반영되고, 미정 사항과 개발을 시작할 다음 작업이 드러나야 한다. 이후에는 “AGENTS.md와 PLAN.md를 읽고 다음 작업을 진행해”로 이어갈 수 있다.

## 구성과 추적성

| 문서 | 역할 |
| --- | --- |
| [AGENTS.md](AGENTS.md) | AI의 판단 기준, 초기화와 개발 원칙 |
| [SPEC.md](docs/SPEC.md) | 목표·범위, F 기능 요구사항과 N 비기능 요구사항, 수용 기준 |
| [TECH.md](docs/TECH.md) | 관련 F/N을 구현하는 설계·계약·기술 선택과 근거 |
| [PLAN.md](docs/PLAN.md) | P 개발 단계, 관련 F/N, 현재 상태·다음 작업·완료 근거 |
| [history/](docs/history/) | 필요한 작업의 변경·결정·검증 이력 |
| README.md | 초기화 후 프로젝트의 설치·사용·개발 안내 |

예를 들어 `SPEC의 F1 → TECH의 F1 관련 설계 → PLAN의 P2(F1) → P2 작업 이력의 F1 검증 결과`로 따라갈 수 있다. 별도 추적표나 검증·결정 문서를 늘리지 않고, 기존 문서의 ID와 링크로 연결한다.

`{{PROJECT_NAME}}`과 `[작성할 내용]`은 채울 위치를 표시한다. 양식을 필요한 만큼 반복하고 불필요한 절은 정리한다. 초기화 후에는 작성 안내와 예시 대신 실제 프로젝트 내용만 남기며, 미정 사항에는 이유와 후속 작업을 적는다.

## 초기화 후 README 양식

README는 방문자가 프로젝트의 목적과 사용 방법을 빠르게 파악하도록 작성한다. 상세 설계·개발 계획·검증 이력은 해당 문서에 남기고, 아래 목차는 프로젝트 성격에 맞게 조정한다.

```markdown
# [프로젝트 이름]

[프로젝트가 무엇이며 왜 유용한지 1~2문장]

## 주요 기능

[사용자에게 중요한 기능과 특징]

## 시작하기

[필요한 환경, 설치, 첫 실행 방법. 아직 불가능하면 현재 상태를 명확히 표시]

## 사용 방법

[대표적인 사용 예시. 프로젝트 성격에 따라 코드·명령·스크린샷 등]

## 문서

[필요한 상세 문서 링크]

## 라이선스

[해당하는 경우 라이선스 안내]
```

초기화 과정에서는 불필요한 절을 제거하고, 존재하지 않는 기능이나 실행 명령은 작성하지 않는다. `.gitignore`는 실제 기술 스택에 맞게 조정하되 lockfile과 공유 설정은 추적 가능하게 둔다.

## 템플릿 유지

개별 프로젝트는 초기화 이후 독립적으로 발전한다. 템플릿 개선을 통째로 덮어쓰지 않고 필요한 부분만 맥락에 맞게 반영한다. 도구·Hooks·별도 관리 문서는 실제 필요가 생겼을 때 추가한다.
